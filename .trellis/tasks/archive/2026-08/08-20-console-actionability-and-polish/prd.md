# 控制台交互可操作性与视觉收口

## Goal

控制台目前把状态显示得很准，但反复不告诉用户**怎么改**。用户在真机点测中提出 9 条问题，归成一句：
**看得见的东西改不动，改得动的东西找不到。**

本任务把这 9 条收口，让每一处"报告出来的问题"都有一条页面内可达的处置路径，并把先前三页遗留的视觉粗糙处一并收拾。

用户是非工程背景。判据不是"信息是否准确"（现在已经很准），而是**"看完这一屏，我知不知道下一步点哪"**。

### 既有约束（沿用，不重议）

- 零构建前端：单文件 HTML + `<script src>`，无打包器/框架/组件库
- 仅回环访问；写端点走 `WRITE_ROUTES` 的 POST-only + loopback-Origin 守卫（KT-PIT-0100：成员资格是路径级，读写不共用路径）
- 每页独立路由 + 独立模板（KT-DEC-0080）
- `shell.css` 是唯一令牌源；其 `:root` 尾部的 legacy 别名块承重（lumen/graph 靠它换肤）
- `lumen.html` 是零回归保护文件
- 文案语域对齐 VS Code 设置文档 / Raycast 手册：陈述句、说清后果、给真实数字
- 共享样式表禁裸标签选择器（KT-PIT-0109）；共享类名准入门槛「≥2 页在用」（KT-PIT-0093）

## Requirements

### R1 — 每个"需要处理"都要有处置路径（对应 F1）
集成页任何标为需处理/多余/缺失的物件，必须在同屏给出可点击的处置动作，或明确说明"这里修不了，去哪修"。当前 15 个孤儿文件属于前者：需要新增清理能力。

### R2 — 提醒缓存可见且可清（对应 F2、T5）
把 `.fabric/.cache/` 的提醒累积状态变成用户可见的一项，并提供清理入口。需区分两件不同的事：**手动永久静音清单**（`hint_dismiss_signals`，配置）与**运行期累积记录**（缓存文件）。

### R3 — 开关要能被找到（对应 T4）
用户带着"我想关掉某个提醒"的意图进集成页时，页面要把他导到正确的开关，而不是重复说"在别处"。

### R4 — 切项目要有可见反馈（对应 T2）
切换范围后，页面须让用户看出"我现在看的是哪个项目"以及"这个值来自哪一层"，即使各项目取值恰好相同。

### R5 — 层级标记必须说实话（对应 T3）
「已在此处设置」只在值确实设在当前查看层时出现；来自上层的继承值须显示其真实来源层。

### R6 — 删除类动作用删除的措辞（对应 T1）
移除一条单独设置的按钮，其标签须表达"移除这条设置"，而非"恢复默认值"。

### R7 — 五页同一个身份（对应 V1）
控制台在任一页面同屏只呈现一个身份。导航条既有的「Fabric 控制台」是那个身份，知识页正文里的旧页头退场。

### R8 — 选中与悬停可读（对应 V2、V3、V4）
导航选中态与悬停态在横向快速移动时边界清晰、不连片；配置行的"已设置"标记与控件聚焦态达到与知识页同级的完成度。

## Acceptance Criteria

> 判据一律为可观测结果；带数字的以真机实测为准。

- **AC1** 集成页上，当前 15 个「多余（本版不再分发）」文件可通过页面内动作清除；执行后重新读取文件状态，该分类计数归零，且「Claude Code / Codex CLI / skill」的"N 项需要处理"随之下降。
- **AC2** 清除动作在执行前列出**将被删除的完整文件清单**并要求一次显式确认；取消后磁盘零变化。
- **AC3** 清除动作只删被判定为 orphan 的路径；对 `ok` / `modified` 状态的文件零触碰（以执行前后 `git status` 与安装记录计数验证）。
- **AC4** 提醒累积记录在控制台可见（至少给出条目数与最旧时间），并有一个清理动作；清理后重新读取，计数下降到 0 或仅剩未过期项。
- **AC5** 每张行为卡在"想关掉它"这个意图下有明确去向：要么卡内直接可关，要么给出指向具体开关的可点击链接（不再出现只说"在上面的某某里调整"而不可点的文案）。
- **AC6** 切换范围后，页面主体区域出现当前范围的名称；且每个配置行标出其取值来源层（本机/项目/默认/环境变量）。
- **AC7** `.frow.mod` 的视觉标记与 tooltip 仅在 `source === 当前查看层` 时出现；从本机层继承的行不再显示"已在此处设置"。真机实测（pcf 集成页，10 个行为参数）：先前 8 行标记、其中 **6 行是继承来的误标**，之后误标 0 行、仅剩 2 行真正设在项目层。
  > 计划期写的是"7 行"，那是估的；真机数是 6。同时那 6 行各自的「恢复默认」按钮也随之消失——它们本来按下去什么都不会移除。
- **AC8** 移除单独设置的按钮标签含"移除/删除"语义；点击后的 toast 与按钮标签语义一致。
- **AC9** 5 个页面（`/` `/graph` `/status` `/config` `/integrations`）任一页同屏只出现一处品牌标识，且五处文案一致为「Fabric 控制台」；知识页正文中的 "Aurora×Terminal · Lumen" 页头不再出现。
- **AC10** 导航横向移动时相邻标签的悬停底色不相接（间距实测 > 0）；选中态除颜色外具备形状差异。
- **AC11** `lumen.html` 有界回归：R7 要求删除其正文页头（`1237-1242`）及修相邻布局，这是本轮**经用户批准的唯一一处** lumen 改动；除该区域外，该页其余渲染改动前后一致。
- **AC12** 新增的写端点（若有）继承 POST-only + loopback-Origin 守卫，并有用例同时断言其 GET=405 与一个读端点 GET=200（KT-PIT-0100 的机制级断言）。
- **AC13** 全量测试与 `tsc --noEmit` 通过；任何新增断言须经变异测试证明会红。

## Out of Scope

- 重写「知识」页（lumen）的内容结构或配色 —— 仅接入统一品牌
- 关联图（`/graph`）的可视化本身
- 新增任何非回环访问面
- 改变配置层级（cascade）的解析规则本身 —— 只改**显示**是否忠实（R5 修的是展示面，不是 loader）
- 彻底停用单个 hook 的 UI（需改客户端配置文件，超出控制台职责边界；本任务只需说清"这里做不到"）

## Key Decisions（2026-08-20 用户拍板）

1. **身份用「Fabric 控制台」** —— 与 CLI 同名，用户在终端敲 `fabric`、在浏览器看到 Fabric，不必记第二个名字。代价是放弃 "Aurora×Terminal · Lumen" 的调性。落地时发现该名称五页均已就位，故实际动作是退掉知识页正文里那个旧页头（见 V1 / R7）。
2. **集成页结论优先、细节折叠** —— 默认只呈现「一切正常」或「N 个文件多余 + 清理按钮」，文件清单收进展开区。用户看不懂这一页，主因就是被文件清单淹没。
3. **删除用「列清单 + 点确认」两步闸** —— 首点展开完整路径清单，二次点击才真删，取消则磁盘零变化。不引入回收目录：孤儿文件是旧版残留、重装也不会重新生成，删错的代价是"下次装回来"而非数据丢失，回收目录本身会积成新的待清理物。
4. **九条一次做完** —— 它们是同一病根的九个切面，分批会重复改同一批文件。工作量集中在两个新功能上，视觉与文案改动都不大。

## Deferred（明确不在本轮）

- **CLI 侧的 `prune` 命令** —— `install never prunes`（`integrations-view.ts:264`）是 CLI 的既有缺口，命令行用户同样会撞上。本轮只在控制台侧补清理能力（孤儿集合那里已算好），CLI 命令另开任务，不阻塞本轮。
