# 控制台界面质感：采用语义令牌 + 重建版式、组件与交互态

父任务：[08-19-console-productization](../08-19-console-productization/prd.md)（W1–W4 已交付：全局作用域、设置分层、集成页、全局项目发现）

## Goal

用户看完前四轮的原话是「不管是质感还是交互之类的……**但是不知道具体是为什么**」，随后补充「知识库数据总览那套语言差不多还是不错的，主要是**后续堆加的一些元素质感跟不上**」，指定 `credit.linux.do` 作为参考、「完全可以照抄」，并要求 **UI/UX 与具体交互都完整观测后再动，不要半成品**。

本轮目标：把 `/status`、`/config`、`/integrations` 三个后加的页面，从"白卡片 + 灰色文字"提升到与内部标杆（`/` 知识总览）同一水平的**成品度**。手段是采用一套成文的语义令牌层与组件规约，而不是逐页调样式——逐页调样式正是它们今天彼此不像的原因。

## Background

### 一次必须记下的自我更正

本 PRD 的**第一版诊断是错的**，在此显式作废：

> 上一版写「病根是字太小（11–13px 占 96%）、最浅那级灰用得太多（48%）」，并据此定了两条验收标准。
> 随后测了用户明确说"好"的 `/` 知识总览页：**它同样是 94% 的文字在 11–13px、最浅灰同样占 48%**；参考对象的表格正文更是只有 11px。
> 即：小字 + 灰字是这几个页面的**共同属性**，无法解释其中一个好看、三个不好看。原诊断把一个无区分力的指标当成了病因。

这条更正是本轮方法论的依据：**代理指标必须先证明它有区分力**，否则照着它干活会修错东西。真正有区分力的指标见 F1。

## 确认事实

### F0 参考对象是 Tailwind v4 + shadcn/ui —— 所以"照抄"成本极低

它的 353 个 CSS 变量里含完整的 shadcn 语义令牌契约（`--background/--foreground/--card/--primary/--muted-foreground/--border/--ring/--sidebar-*/--chart-1..5`）。

**要抄的不是某个人的审美，是一份公开成文、被大量项目验证过的令牌表；而且它全部是 CSS 自定义属性——零构建即可采用，不违反我们"零构建前端"的硬约束。** 不引入 Tailwind、不引入 React、不引入组件库，只把**语义令牌层与组件规约**搬进 `shell.css`。

### F1 真正的差距（三页实测对比）

| 指标 | 我们 `/config` | 参考对象 | `/` 知识总览（合格线） |
| --- | --- | --- | --- |
| **> 14px 的字号档数** | **1**（且是导航栏标题） | **2**（30px 页标题 + 16px 区块标题） | **2**（32 + 大数值） |
| 全页最大字号 | 15px | 30px | 32px |
| 主导字重 | **400 占 81%** | **500 占 50%** | 400 占 86%，但有 5 档在用 |
| SVG 图标 | **0** | 38（16px lucide 为主） | 有 |
| 有阴影的元素 | **17** | **6**（且只在浮层上） | — |
| 1px 发丝线 | **58** | 22 | — |
| 设置/表格行高 | **98–140px** | 33px（表格）/ 60px（列表） | — |
| 文档高度 | **2709px** | 951px | 470px |
| 过渡时长档数 | **1**（`.toast` 的 .18s） | **4**（.15 / .2 / .3 / .4s，各管一类事） | — |

第一行是本轮真正的病因指标：它在"好看的"和"不好看的"之间有区分力，而字号分布没有。

### F2 病因一：没有视觉锚点，且层级只有一个轴

我们整页最大的字是导航栏标题 15px——正文里没有任何东西比"Fabric 控制台"更重要，眼睛没有落点。

参考对象的层级是**两个轴分工**：`h1` 30px（一行内混字重，名词 600 / 数值 400）、`h2` 16px/600。同一个 14px 上，标签页用 700、卡片标题用 500——**size 管第一级，weight 管第二级**。我们只有"大且粗 / 小且不粗"一个轴，且最大档位被浪费在了 chrome 上。

### F3 病因二：三套分隔系统同时开着

我们有 58 条发丝线 **+** 17 处阴影 **+** 16 个圆角卡片，三种"这是一块"的信号叠用。

参考对象的规则是一条：**阴影只出现在浮层上**（对话框 `shadow-2xl`、下拉菜单 `shadow-md`、toast `0 4px 12px`），**内容区的卡片一律 `shadow-none`**——首页的卡片甚至连边框都没有（`border-0 shadow-none`），只靠 24px 间距和一个区块标题分块。

更具体：我们的 `--shadow` 是 `0 4px 20px -2px` 的**大模糊柔光**；参考对象最重的常规阴影是 `0 1px 3px 0 + 0 1px 2px -1px`。柔光正是"发虚、廉价"的直接来源。

### F4 病因三：正文字重错配

参考对象表格正文是 **11px / 500**，表头 **13px / 500 且用满色 `--foreground` 而不是灰**。我们 `/config` 的 11–12px 正文是 400 + 三级灰。

**同样 11px，500 比 400 明显更"实"**；表头用满色则给了列一个抓手。这是最便宜的一条改动，也解释了为什么"小字"在它那里不显廉价、在我们这里显。

### F5 病因四：零图标 + 零组件词汇

我们 SVG 图标数为 **0**。参考对象 38 个，且图标规约写死在组件里：
`[&_svg]:pointer-events-none [&_svg]:shrink-0 [&_svg:not([class*='size-'])]:size-4`
——**没写尺寸的图标一律 16px，一律不响应鼠标、一律不被压扁**。这解释了为什么它们的图标"到处都对"，也解释了用户说的"堆加的元素质感跟不上"：我们所有信息都靠纯文字扛。

组件词汇同样缺：它有 badge / card / progress / tabs / switch / kbd / menu / dialog / empty-state；我们只有"白卡片"和"灰文本行"两种。

### F6 病因五：交互态不成体系

参考对象 DOM 中的状态变体频次：`focus-visible ×127`（**最高，是 hover 的两倍**）、`hover ×65`、`aria-invalid ×64`、`disabled ×60`、`data-[state=open] ×32`、`data-[active=true] ×32`。

我们目前只有 `.seg` 与 `.scope-select` 写了 `:focus-visible`，`:disabled` 只在 `.fctl` 内有一条 `opacity:.5`，没有 `aria-invalid`、没有 open/active 数据态。

两条实测细节值得单独抄：

- **hover 与选中用不同维度**。侧栏项 hover 改底色、选中改字重+文字色——所以**悬停在当前页上仍然有反馈**。同维度做会导致"点哪儿都没反应"。
- **菜单项高亮写的是 `focus:` 而不是 `hover:`**，鼠标悬停由库转成 focus，于是**键盘和鼠标共用同一个高亮态**，不会出现"键盘选中了但看不见"。

### F7 病因六：动效为零，且缺少"事件分类"

参考对象四档时长各管一类事：`.15s` 交互态、`.2s` 内容替换、`.3s` 布局尺寸、`.4s` toast。过渡属性一律是颜色类（`color, background-color, border-color, outline-color, fill, stroke`），**没有一处对布局属性做 `all`**；位移与缩放只出现在**浮层入场**那一帧（`zoom-in-95` + `slide-in-from-top-2`）。

我们只有 `.toast` 一条 `opacity .18s`。四档的价值不是"动起来好看"，是**用户不用看内容就知道发生了哪一类事**。

### F8 病因七：确认模型反了

实测：点掉「显示通知铃铛」开关的那一刻，**顶栏铃铛当场消失**。没有 toast、没有"已保存"、整页没有保存按钮。

对照我们 `/config`：每行一枚常驻保存按钮（共 16 枚），改完弹一条 toast 说"已保存"。用户要先信这条 toast，再自己去别的页面确认真生效了。

**但这条有边界**：它只在"改动能立刻在当前视野里看见"时成立。Fabric 的大多数配置（阈值、频率）改完当前视野里没东西可变，那就仍然需要明确回执。所以规则不是"删掉所有保存按钮"，而是——**能当场看见结果的，让结果本身当回执；看不见的，才给回执，并且回执要说清"什么时候生效"。**

### F9 我们的主色本来就对

`--accent: #2563eb` 与参考对象的 `--primary`（`lab(49.0 30.3 -71.9)` ≈ `#2563eb`）**几乎是同一个蓝**。

→ 采用新令牌**几乎不改主色**。真正会变的是中性色：暖调 Apple 灰（`#1d1d1f / #48484a / #86868b`，三级）换成冷调 zinc（两级）。这是一处真实但很小的色彩变化，且是"三级文字色的最浅一级被用得最多"这个倒挂的结构性解法。

### F10 全局左侧栏：查证后否决（原推荐推翻）

上一版把"是否给所有页面加左侧栏"列为待确认项，并推荐"是"。查证 `lumen.html` 后**推翻自己的推荐**：

- `lumen.html:1221` 已有 shell 的 `.navbar`，`:1240` 起**还有它自己的 `<header>`**（brand + 搜索 + 视图切换），`:348` 起是 `.layout{grid-template-columns:340px 1fr}` 的知识树侧栏。
- 再加一条全局侧栏 = **侧栏 + 340px 知识树 + 详情**三栏，1440px 已紧、1024px 不可用。

→ **不做全局左侧栏。统一到一条重建过的顶栏**（52px、图标 + 文字、四态齐备、8px 圆角、焦点环走 `--ring`），五个页面共用。参考对象用侧栏是因为它有 8 条主导航；我们只有 5 条，顶栏放得下。

这条属于 Trellis「能查代码就别问用户」：它是技术事实，不是产品偏好。

## Requirements

### R1 语义令牌层（`shell.css`，唯一真源）

- 新增：`--background/--foreground/--card/--card-foreground/--popover/--primary/--primary-foreground/--secondary/--muted/--muted-foreground/--accent/--accent-foreground/--destructive/--border/--input/--ring`，浅深两套按观测文档 §1。
- 文字色收敛为**两级**（`--foreground` / `--muted-foreground`）。
- 深色模式用语义映射：`--border` 用半透明白、`--destructive` 变浅——不再逐个手填深色灰。
- 现有令牌名（`--text` / `--surface` / `--accent-light` / `--text2` …）**保留为别名**指向新令牌，使既有页面 `<style>` 与 `lumen.html` 零改动仍然正确。

### R2 排版令牌与两轴层级

- 字号阶梯 `--fs-1..7` = 11 / 12 / 13 / 14 / 16 / 20 / 30；字重 `--fw-normal/medium/semibold/bold` = 400/500/600/700。
- 层级两轴分工：页面标题走 size（30px），区块标题走 weight（16px/600），同一 14px 上用 500/700 分角色。
- **数据密集处正文字重改 500**，表头用满色 `--foreground`。

### R3 收敛为一套分隔系统

- **阴影只允许出现在浮层上**（toast、菜单、对话框）。内容区一律 `box-shadow: none`。
- 阴影令牌换成紧实薄阴影：`--shadow-sm: 0 1px 2px 0 rgb(0 0 0/.05)`、`--shadow-md: 0 4px 12px rgb(0 0 0/.1)`。
- 圆角统一由 `--radius: 10px` 派生 `--radius-sm/md/lg` = 6/8/14。
- 内容分块优先用「区块标题 + 间距」，其次 1px 发丝线，卡片只用于"卡内确有多条内容"。

### R4 图标系统（内联 SVG，零构建）

- 一套内联 SVG 图标，随主题变色（`stroke: currentColor`、`stroke-width: 2`、`fill: none`）。
- 规约由 CSS 统一给，不逐处写：容器内 `svg` 默认 16px、`flex-shrink: 0`、`pointer-events: none`；显式尺寸类可覆盖。
- 覆盖：导航 5 项、区块标题、状态语义（正常/注意/故障）、可点操作、空态。

### R5 组件词汇

按观测文档 §6 的实测规格落地，类名统一 `fx-` 前缀以避免与 `lumen.html` / 各页既有类名冲突：

`fx-btn`（primary/ghost/danger + 四态）、`fx-icon-btn`（36×36）、`fx-badge`（10–11px/500、全圆）、`fx-card`、`fx-stat`（小标题 + 大数值）、`fx-kv`（左 label 右值）、`fx-table`（th 13/500 满色、td 11–12/500、行高 ≤40px、空值写 `–`）、`fx-tabs`（选中变色 + 2px 下划线、字重不变以免宽度跳动）、`fx-empty`（居中图标 + 主文案 + 副文案，无插画无边框）、`fx-kbd`、`fx-switch`。

### R6 顶栏重建（不做全局侧栏，见 F10）

- 52px 顶栏：品牌 → 5 条导航（图标 + 文字，选中态改文字色 + 2px 下划线）→ 弹性空隙 → 作用域切换器 → 图标操作组（主题切换）。
- 选中态与 hover 用**不同维度**（选中改色 + 下划线，hover 改底色），保证悬停在当前页仍有反馈。
- 每页内容区顶部为页面标题行：`h1`（30px，混字重）+ 右侧主操作 + 通栏发丝线。

### R7 交互态成体系

- `:hover` / `:focus-visible` / `:active` / `:disabled` 四态在**所有**可交互元素上齐备。
- 焦点环统一 `outline: 2px solid var(--ring); outline-offset: 2px`，与 hover 同等对待。
- hover 用"叠一层 accent 底"或"降不透明度"实现，不手调新颜色——保证不跑色。
- 表单错误态用 `[aria-invalid="true"]` 驱动，不逐页各写各的。

### R8 动效四档

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--dur-1` | `.15s` | 交互态：hover / focus / active / 开关 |
| `--dur-2` | `.2s` | 内容替换：列表重绘、区块切换 |
| `--dur-3` | `.3s` | 布局尺寸变化 |
| `--dur-4` | `.4s` | toast 进出 |
| `--ease` | `cubic-bezier(.4,0,.2,1)` | 全部 |

过渡属性只允许颜色类，**禁止 `transition: all`**；位移/缩放只允许用在浮层入场。异步动作有进行中态（spin），并遵守 `prefers-reduced-motion`。

### R9 承接上一版仍然成立的具体缺陷

- **重复标题**：`/integrations` 的 7 个「调节项」按实际归属改名；同一页内不出现重复小节标题。
- **同名行**：`/config` 两行 `underseed_node_threshold` 标签都写「团队 store」，必须各自写出 store 名。
- **预设摊开**：「提醒频率」三档共摊 24 个数字；改为档名 + 一句后果，数字收进展开区（不改父任务 AC6 的逐键反推逻辑）。
- **长标识符**：sha256 / uuid / 绝对路径整串直出且被裁切；改为截断 + 复制 + 可展开。
- **行高**：`/config` 行 98–140px；说明收进展开，行高压到 ≤48px。
- **常驻按钮**：16 个保存/恢复按钮常驻；改为**改动后才出现**（F8 的有边界版本：保留回执，因为改动结果当前视野看不见）。
- **孤儿网格**：`/status` 3 张卡在 2 列网格里留空洞。

### R10 不变量

- 零构建前端；只听 loopback；每页独立路由 + 独立模板（KT-DEC-0080）。
- 不引入 Tailwind / React / 组件库 / 图标字体 / 任何构建步骤——**只搬令牌与规约**。
- `shell.css` 是令牌唯一真源；字段自省派生不可破（KT-DEC-0035）；一个 key 一个可写位置（KT-MOD-0004）。
- `lumen.html` 与 `graph.html` **不改文件内容**，仅通过令牌别名继承新配色；父任务 AC1–AC19 全部不回归。

- [ ] **AC1** 三页 computed `font-size` / `font-weight` 取值集合 ⊆ R2 令牌集；无令牌外的手写值。
- [ ] **AC2** 每页存在 ≥1 个 ≥28px 的视觉锚点，且它承载该页最重要的内容（不是 chrome）。基线：最大 15px 且是导航栏标题。
- [ ] **AC3** 三页 > 14px 的字号档数 ≥ 2（基线 1）。
- [ ] **AC4** 文字色只出现 `--foreground` 与 `--muted-foreground` 两级（基线三级，最浅一级占 48%）。
- [ ] **AC5** 内容区（非浮层）有阴影的元素数为 **0**（基线 17）；`--shadow-*` 模糊半径 ≤ 12px（基线 20px）。
- [ ] **AC6** 三页 SVG 图标数各 ≥ 12（基线 0），且切换深色后颜色随之改变（`currentColor` 生效）。

## Out of Scope

- 引入 Tailwind / React / 任何组件库或构建步骤。只搬**令牌与规约**（F0：它们本来就是纯 CSS 变量）。
- 全局左侧导航栏（F10：查证后否决，改为重建顶栏）。
- 新增功能面：本轮不加任何 Fabric 能力，只改既有信息的呈现（父 C1 / KT-DEC-0072）。
- 改写 `lumen.html` / `graph.html` 的页面内容（R10：只通过令牌别名继承）。
- 把 UI 指标做成 CI 门禁。探针是前后对照工具；固化成闸门需要先解决口径收敛（KT-GLD-0022），成本远大于本轮收益。
- 移动端完整适配。控制台是本机 loopback 工具；768px 以上不裁切即可。
- 抄参考对象的**业务形态**（积分、集市、排行榜）与它的拟物收据式"高光"（观测文档 §7.2：整套系统严格统一、只在一处破例；我们没有对应的情感落点）。
