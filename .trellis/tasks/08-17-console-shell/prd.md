# 控制台骨架：preview 扩为多页 + 写通道安全边界

父任务：`.trellis/tasks/08-17-fabric-console`

## Goal

把 `fabric preview` 从单页只读知识浏览器，扩成一个可承载多个功能页、且具备写通道的本机控制台骨架——但本子任务**只交付骨架与安全边界**，不交付任何具体功能页。

## Requirements

- **R1** 多页路由：每个功能页 = 独立服务端路由 + 独立模板文件。禁止把新数据改写成既有模板认识的形状注入 `lumen.html`（KT-DEC-0080 原则）。
- **R2** 视觉一致：新页沿用现有 Lumen 风格（用户明确认可现有观感）。样式需可共享，不得每页复制一份 CSS。
- **R3** 零构建：单文件 HTML、系统字体栈、无外部依赖、离线可用。不引入前端构建链。
- **R4** 写通道：开放 POST 端点能力，供后续子任务挂载。
- **R5** 导航：页面之间可互相跳转，用户不需要记 URL。

## Constraints（安全边界，缺一不可）

用户决策：**只监听 127.0.0.1，不做鉴权**。理由是能连上 loopback 的进程本来就能直接读写配置文件，加密码防不住真实威胁只增摩擦。该决策成立的前提是下面三条同时落地：

- **C1** 绑定地址硬编码 `127.0.0.1`，不存在任何 flag / 配置 / 环境变量能改成 `0.0.0.0`。需有测试锁死这一点。
- **C2** 写端点必须是 `POST`，且校验 `Origin` / `Host` 为 loopback。
  > 这不是鉴权，是防止**非用户发起**的请求：外部网页可以让浏览器去打 `127.0.0.1:7777`（DNS rebinding / CSRF 类）。「不做鉴权」的决策是「不验证用户身份」，不等于「接受任意来源的请求」。
- **C3** 写操作一律走内核既有写入路径，不新增写文件方式。
- **C4** 只读行为零回归：现有 `/` `/graph` `/api/knowledge` `/api/revision` 与 `?all=1` 语义不变。

## Acceptance Criteria

- [ ] AC1 至少两个页面（现有知识页 + 一个新页）可互相跳转，视觉一致。
- [ ] AC2 有测试断言服务只在 `127.0.0.1` 可达，且不存在改绑地址的入口。
- [ ] AC3 有测试断言：伪造非 loopback `Origin` 的 POST 被拒绝。
- [ ] AC4 有测试断言：写端点不接受 `GET`。
- [ ] AC5 既有 preview 测试（`preview-graph` / `preview-port-fallback` / `preview-source-toggle` / `preview-title`）全绿。
- [ ] AC6 样式为共享来源，改一处两页同时生效。

## Out of Scope

- 具体功能页内容（配置页归 `console-config-view`，项目页归 `console-version-upgrade`）。
- 鉴权 / 多用户 / 远程访问。
