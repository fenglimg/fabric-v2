# 控制台产品化：全局视角 + 设置面重构

## Goal

把已跑通的控制台从「功能齐、但要懂 Fabric 内部概念才看得懂」推进到「装上就能用」：

1. 作用域从「你从哪个目录启动」升级为**全局视角 + 可切换项目**；
2. 配置页从**参数表**变成**设置面**（常用在前、高级收起、文案说清后果）；
3. MCP / hook / skill / 客户端这层**从完全不可见变成可见、可关、可修**。

父任务 [08-17-fabric-console](../08-17-fabric-console/prd.md) 的产品化动机（AC7/AC8）已写明判据是「第一次打开就看懂」。首轮实现达到了「信息查得到」，未达到「不懂 Fabric 也看得懂」——本任务是那条判据的兑现轮。

## Background

用户 2026-08-19 的三条原话及其指向：

| 原话 | 指向 |
| --- | --- |
| 「状态区域还是只能显示当前启动的具体目录下…本意上是不管哪个目录开启都是全局的视角，可以允许切换到其他 project」 | 作用域模型错位 |
| 「一般人使用也没有必要了解这么多概念」「不是这么 geek 的感觉」 | 配置页把内部模型直接当主界面 |
| 「重点应该是如 mcp，skill，hook…归纳后挑战是否需要允许配置」 | 安装物件面完全缺失，且现有配置项需要被挑战 |

用户同时明示「我自己也不是完全的产品，有时也不知道什么决策最佳」→ **产品决策由 AI 提方案并对标同类产品，用户只做认可/否决**。
风格约束：视觉语言（`shell.css` 令牌）不变；文案语域**参照 VS Code 设置文档 / Raycast 手册**——陈述句、说清后果、给出实际数值，不要为白话而白话。

## 确认事实（代码实证）

### F1 作用域现状
`collectConsoleStatus(projectRoot)`（[status.ts:46](../../../packages/cli/src/console/status.ts:46)）三个数据源全部按 `projectRoot` 取；知识页与关联图同理。**配置页已是机器视角**（[global-config-view.ts:296](../../../packages/cli/src/console/global-config-view.ts:296)），`launchDir` 只决定哪一行标 `isCurrent`。→ 待改的是状态 / 知识 / 关联图三页。

### F2 切换器的能力边界（硬约束）
机器级注册表 [project-registry-io.ts](../../../packages/cli/src/store/project-registry-io.ts) 以绝对路径为键，由 `fabric install` 写入。
**KT-PIT-0050：`project_id → repo 路径` 的反向映射在系统中不存在。** 因此只有登记过路径的项目能被切换过去；只在全局配置里出现的 `config-only` 项目有 id 无路径，永远无法作为工作区视角打开。
实测本机 `~/.fabric/state/` 下**尚无 projects.json**——所有存量项目（含本 repo）都未登记。→ 切换器上线首日可能只有 0～1 个可选项，**空态是主路径**。

### F3 配置面现状
18 个面板字段从 [fabric-config-introspect.ts](../../../packages/shared/src/schemas/fabric-config-introspect.ts) 自省派生（4 组、三种 home）；项目 schema 实际约 40 键，其余 22 键（检索调参、信誉半衰期、孤儿降级…）**故意不进面板**，理由写在代码里：「一个你判断不了的面板项就是噪声」——本任务不推翻这条。
18 项里 **8 项是「多久提醒一次」的数字**，普通用户一个都判断不了；真正能自判的约 6 项。这是 geek 感的主要来源。
完整普查见 [research/config-surface-census.md](research/config-surface-census.md)。

### F4 安装物件面：控制台目前 0 可见
8 个 hook 入口脚本 + ~15 个 lib + 两份客户端 hook 配置、6 个 `fabric-*` skill、每客户端一条 MCP 注册、`AGENTS.md` 托管块、两个客户端（Claude Code / Codex CLI）——全不可见。
**关键发现：hook 的可关闭行为已经有 config key**（`cite_policy_enabled` / `self_archive_policy_enabled` / `cite_recall_nudge` / `nudge_mode` / `hint_dismiss_signals`）。→ 行为开关一律绑既有 key，不新增「装不装」的布尔清单，天然绕开 KT-PIT-0067（第三份真相）。

### F5 不变量
- 字段自省派生不可破（KT-DEC-0035）；一个 key 一个可写位置（KT-MOD-0004）。
- 零构建前端；只听 loopback；每页独立路由 + 独立模板（KT-DEC-0080）。
- `lumen.html` 未迁令牌，是已知有界债务——本轮只改它的 navbar 与取数参数。

## Requirements

### R1 全站作用域切换器
- 导航栏常驻切换器，默认「本机」；选中项目后状态 / 知识 / 关联图 / 设置**一起**切换，并有可见的作用域标识。
- 「本机」作用域本身有内容：版本三处、已登记项目列表、挂载的知识库。
- 切换器只列**已登记路径**的项目；未登记的存量项目必须在界面上讲清「为什么少」和「怎么补」，不能让用户误以为自己只有这几个项目。
- 作用域解析失败（路径已失效 / 只有 id 无路径）**显式报错，不静默回退**。

### R2 设置页三层信息架构
- 常用（约 6 项）/ 高级（默认折叠）/ 跨层搜索；搜索命中高级项时自动展开高级区。
- 来源层不再是标题旁的标签：**改过的项左侧一道竖条**，来源层降为详情。
- 每项可**恢复默认**（补上「per-project 覆盖加得上、删不掉」的现有缺口）。
- **未登记的新字段自动落「高级」并照常渲染**——不得因呈现注册表未更新而静默消失。

### R3 归档提醒频率预设
- 8 项阈值合成一个三档选择器（低频 / 标准 / 高频），每档在界面上**标出其实际阈值**。
- 预设不落任何 `preset_name` 字段：读取时逐键全等反推档位，不匹配显示「自定义」。
- 8 项在高级区仍可逐项修改。

### R4 配置项增删（挑战结论）
**新增**：`hint_dismiss_signals`（「不再提醒这类事」逃生阀，目前只能手改 JSON，而提示语本身就在教用户去改它）；`embed_endpoint` / `embed_model`（key 只显示已设置/未设置，永不回显）；`active_write_store`（新用户最常问的「我记的东西存哪」）。
**移出主界面到高级**：`fusion`、`underseed_node_threshold`（现按每个 store 各渲染一遍 → 三张同样的卡）、`archive_hint_cooldown_hours`、`maintenance_hint_cooldown_days`、`review_stale_pending_days`、`default_layer_filter`、`audit_mode`。
**新增状态表达**：`embed_enabled=true` 但嵌入服务不可用时显示「已启用 · 未生效」+ 下一步，而不是只显示 `true`。

### R5 集成页
- 清单：哪些客户端接了、MCP 通没通、装了哪些 hook / skill、托管块有没有漂移。
- 开关单位是**行为**（「编辑前提示检索」）而非文件；物理文件只读。
- 一键修复：动作枚举仅 `install` / `doctor --fix`，目标由作用域推导，请求体不带路径，输出可见。
- 清单以**文件系统**为唯一真源。

### R6 文案语域
陈述句 + 说清后果 + 给出实际数值。内部 key 名沉入详情。不使用口语化修辞。

## Acceptance Criteria

- [x] AC1 从两个不同目录启动控制台，`?scope=<同一项目>` 返回的四页内容一致——作用域来自参数，不来自启动目录。
  - **唯一例外（诚实的信息下限，非设计选择）**：启动目录**自己那一行**的 `path` 是当场观测到的。机器上没有任何 `project_id → 目录` 的反查（KT-PIT-0050），所以从别处启动时这个路径**根本不存在可供上报**，那一行只能以裸 uuid 呈现且无法作为作用域打开。差异的消除办法是在该仓库跑 `fabric install`——路径进了登记表，任何控制台都能看见。测试以「把当前行归一化回无路径形态」表达此例外，因此路径泄漏到**其他**行仍会失败。
- [x] AC2 切换到另一个项目后，状态 / 知识 / 关联图 / 设置四页同时反映该项目；界面上能一眼看出当前作用域是谁。
- [x] AC3 作用域指向已失效或无路径的项目时，页面显示原因与下一步，且**不显示任何其他项目的数据**。
- [ ] AC4 设置页主界面可见项 ≤ 8；其余项在「高级」内且可被搜索命中（命中时自动展开）。
- [ ] AC5 往面板字段表加入一个呈现注册表未登记的键，它出现在「高级」区——不消失。
- [ ] AC6 选中一档预设后，8 项阈值在高级区显示为该档数值；随后改动其中任一项，档位显示变为「自定义」。
- [ ] AC7 任一已修改项可恢复默认；恢复后该项左侧竖条消失，且生效值等于**下一层**的值（不得恰好等于代码默认值而假绿）。
- [ ] AC8 `embed_enabled=true` 且嵌入服务不可用时，界面显示「已启用 · 未生效」并给出下一步。
- [ ] AC9 集成页列出两个客户端的接入状态、MCP 状态、hook/skill 清单与漂移；删掉一个已装 skill 文件后清单如实反映缺失。
- [ ] AC10 对有漂移的项目点「修复」，动作输出可见，完成后漂移消失；`machine` 作用域下不提供修复入口。
- [ ] AC11 `/api/repair` 与 `/api/config/preset` 受既有写通道守卫约束：非 POST、跨源 Origin、非法 action 全部拒绝且不产生副作用。
- [ ] AC12 既有 `preview-*` 只读测试全绿（父 AC5 不回归）。
- [ ] AC13 每页在「空数据 / 数据不全 / 获取失败」三态下都显示原因与下一步（父 AC7）；界面不出现未翻译的内部术语（父 AC8）。

## Out of Scope

- 扩功能面：控制台只做 Fabric 现有能力的可达性（父 C1，KT-DEC-0072）。
- 鉴权 / 远程访问 / 多用户（loopback-only 不变）。
- 把 22 个 JSON-only 调参键搬进面板（与产品化方向相反）。
- `lumen.html` 迁移到 `shell.css` 令牌（已知有界债务，另有其任务）。
- 自动扫描磁盘发现未登记项目（存量项目仍靠各跑一次 `fabric install` 登记，父任务已定）。
